## Findings (ranked)

**1. Resolution is placeholder-based, not fixed-filename** — `resolve_declared_output_paths` (runner.py:400-431) expands each `outputs[].path_template` via `_placeholder_values` (runner.py:1162-1191): `{out}`, `{brief}`, `{brief_out}`, `{brief_slug}`, every input (incl. defaults), plus each output's own resolved path keyed by `output.name` (1186-1190). So `{out}/{iteration_id}.mp4` works if `iteration_id` is an *input*; there is **no** built-in `{output_name}`/`{iteration}` placeholder.

**2. Consumers of `result.outputs`** — populated only on `returncode == 0` via existence-filtered `_resolve_declared_outputs` (runner.py:595, 660, 731), keyed by declared **name**. Arnold: CAS hit/miss/evidence all key on `output.name` (step_adapter.py:502-513, 534-546, 740-765); missing → `missing_declared_outputs` failure (767-784). Orchestrator output collection matches `output.name`/placeholder (orchestrator/runner.py:592-596, 765-766).

**3. render executor.yaml** — `video` → `{out}/hype.mp4`, `provenance` → `{out}/hype.mp4.provenance.json` (137-154); argv `--out {out}/hype.mp4` (27); cache sentinel `"hype.mp4"` (8).

**4. Hype pipeline is subprocess/hardcoded, not declared-name propagation** — render sentinel `("hype.mp4",)` (steps.py:357) and `--out {brief_out}/hype.mp4` (368); validate consumes `--video …/hype.mp4` (405); also runner.py:223,294,444; cut/resume.py:170; run.py:1129 enforces `out_path.name == "hype.mp4"`.

## Verified facts
- Declared outputs resolve via input/out placeholders only; consumed by name everywhere; Arnold CAS digest includes `output.name` (444-448).

## Unknowns
- Whether `brief`/iteration is in `request.inputs` for CAS identity (Arnold identity covers inputs only, 386-396) — dynamic names from `brief_out` may not change the CAS key.

## Risks
- Renaming breaks sentinel, command builders, validate, cut-resume, Arnold evidence/CAS keys (name is in digest), cache sentinel.
- Name derived from non-input placeholders → cross-iteration CAS cache poisoning.

## Suggested approach
Add an `iteration` *input* to the render executor, template `{out}/{iteration}.mp4` in path_template + argv + sentinel, then thread `--iteration` from hype steps.py — all consumers stay name-keyed; identity varies per iteration.
