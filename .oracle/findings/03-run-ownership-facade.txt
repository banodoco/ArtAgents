## Ranked findings

**1. Run creation & artifacts at render time.** `CapabilityRunner.run` (capability_runner.py:106-154) → `prepare_project` → `_prepare_project_request` (executor/runner.py:913-953) → `prepare_project_run` (project/run.py:145-288): run_id via `generate_run_id()` (run.py:252), run_root (run.py:253-257), `run.json` written RUNNING (run.py:279-280), logs opened (runner.py:628). When `rendering.render` executes, existing artifacts: run_root + run.json + logs + timeline/assets inputs; `hype.mp4`/provenance written by the subprocess; `finalize_project_run` mirrors hype artifacts (run.py:405-419).

**2. No run from bare subprocess.** Run records are created only by `prepare_project_run`/`write_run_record` (run.py:145,431); `subprocess.run` (runner.py:637) never reaches them. A plain `subprocess.run([...])` inside an executor creates no project run — ledgering is exclusively the executor runner's job.

**3. Facade inputs/outputs & engine validation.** `executor.yaml`: command `{python_exec} -m astrid.packs.rendering.executors.render.run --timeline {timeline} --out {out}/hype.mp4` (yaml:20-28); inputs timeline/assets_registry/theme/engine/keep_previous_renders (yaml:74-109); outputs hype.mp4 + provenance (yaml:137-154). `--engine` choices `("remotion","ffmpeg","hybrid")` validated by argparse (render/run.py:1561), re-checked in `render()` (run.py:1437-1438).

**4. `_normalize_render_command_compat` shim** (runner.py:1240-1261): only for `rendering.render` with a theme value; when `--assets` sits after `--out`, it removes the `--assets <value>` pair and reinserts it immediately after `--out`. Net effect on the appended input_args order: `--out O --assets A --theme T --engine E` — assets adjacency to `--out`, not theme reordering.

**5. Guard.** `guard_canonical_entrypoint` (entrypoint.py:37-56) exits 2 unless `ASTRID_INTERNAL_INVOCATION` is set or the ContextVar matches. render/run.py:7 calls it; the executor subprocess passes because `_command_subprocess_env` sets `ASTRID_INTERNAL_INVOCATION=1` (runner.py:1130) plus `ASTRID_PROJECT_RUN=1` (runner.py:1128; run.py:92).

## Verified facts
- Subprocess invocation passes guard via env; does not create a nested run.
- Engine allowed: remotion, ffmpeg, hybrid (argparse, run.py:1561).

## Unknowns
- Why assets must sit directly after `--out` (shim intent undocumented); whether any caller relies on stale ordering.

## Risks
- Nested runs if facade invokes `astrid executors run` instead of the module.
- Stale argv: auto-forwarded/input_args ordering changes silently reorder flags.
- Direct-module bypass: any call without `ASTRID_INTERNAL_INVOCATION=1` exits 2.

## Suggested approach
Invoke the module subprocess with `ASTRID_INTERNAL_INVOCATION=1` + `ASTRID_PROJECT_RUN=1` env, keep `--out` before `--assets`, and bypass the executor runner only for the render module, not for nested executor dispatch.
