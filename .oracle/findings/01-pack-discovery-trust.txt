# Pack discovery & trust — ranked findings

**1. Precedence order** — `SOURCE_KINDS = ("source","local","extra","env","installed")` (discovery.py:31). `discover_pack_metadata()` (discovery.py:79-164) walks exactly that order: repo source packs (115-118), project `local` pack (120-123), `extra_pack_roots` (133-139), `ASTRID_PACKS_PATH` roots (140-149), then `installed_pack_roots()` (150-162). `priority_index` = list position, lower wins (106-113). Per-root scanner: `discover_packs()` (loader.py:84-107), raises on duplicate ids (103-104). **Active installed revisions** = resolved `active` symlink via `active_pack_roots()` (store.py:195-216, 121-133); `InstallRecord.active` bool exists (store.py:56, 318-351) but discovery keys off the symlink only; `mark_inactive()` unlinks it (store.py:231-237).

**2. Trust** — No `trusted` field exists (grep: 0 hits). Trust is procedural: `validate_pack` gate (install_local.py:199-215), exact-phrase acknowledgement `_confirm_trust` (install_trust.py:202-214), audit labels `trust_method/actor/acknowledged_at/tier`, `permissions_accepted` (store.py:72-79; install_local.py:404-433). `trust_tier` = source type only (install_local.py:292-293). Downloaded-but-uninstalled packs sit in `staging/` (store.py:135-137) with no `active` symlink → **not discoverable, not executable**; staging is cleaned on failure (install_local.py:263-268, 348).

**3. Permissions** — Vocabulary `PACK_PERMISSION_IDS = ("project_files","network","subprocess","environment","accelerator","external_services")` (_common.py:42-49); declared in pack.yaml `permissions:` (id/reason/access/services), normalized/validated (permissions.py:70-105), loaded into `PackDefinition.permissions` (loader.py:132,149). **Disclosure-only**: `V1_TRUST_BLOCK` hardcodes `sandbox:"none"`, `permission_enforcement:"disclosure_only"` (validate.py:98-102); install_trust.py:166-169; cli_inspect.py:280; zero references in `astrid/core/execution`. Only consumers: display, serialization, SDK safety metadata (sdk/discovery.py:183-193).

**4. Result shape** — `tuple[DiscoveredPack]` (discovery.py:35-76): `pack`, `source_kind`, `priority_index`, props `id`/`pack_dir`/`executor_roots()`/`orchestrator_roots()`/`element_roots()`/`skill_roots()`. No `active` field. Callers: element/registry.py:207,303; skills/discovery.py:143 (filters extra/installed); sdk/discovery.py:140; generation verbs/features/backends; render/run.py:1161; executor+orchestrator use `discover_packs_ordered` (executor/registry.py:294) which drops source_kind.

## Verified facts
- Order: source < local < extra < env < installed (discovery.py:31,115-162)
- Active = `active` symlink resolution (store.py:121-133,195-216)
- Trust = procedural ack, not a persisted boolean (install_trust.py:202-214)
- Permissions unenforced; disclosure-only (validate.py:98-102)
- Staging packs undiscoverable/unexecutable (store.py:135-137,455-462)

## Unknowns
- Git install identity verification beyond recorded `commit_sha` (install_git.py)
- Whether render/run.py:1161 or SDK paths filter trust before execution
- Symlink vs `record.active` divergence handling

## Risks
- Executor/orchestrator registries auto-execute every discovered pack (incl. env/extra/installed) with no trust filter; permissions never enforced — installed code runs with user process permissions.
- No signature/digest verification at discovery/load (`manifest_digest` recorded, never checked); `ASTRID_PACKS_PATH` is an implicit execution vector.

## Suggested approach
Add a trust gate at the discovery→registry boundary: only packs with a verified install record (acknowledged trust + digest) are executable; treat source/local/extra/env as untrusted for the plugin surface. Since permissions are unenforced, default-deny (refuse execution) until a runtime permission enforcement layer exists.
