## Verified facts
Complete shared-state mutation set: 3 package registries, 15 shims, symlink+pointer, state json. All generation occurs pre-server/pre-subprocess inside `render()`.

## Unknowns
Whether concurrent `gen-types` runs are expected during renders; Windows pointer semantics.

## Risks
**No lock exists today.** Any concurrent render (or dev `gen-types`) racing `_regenerate_element_registries` can interleave: stale state written after fresh generation, symlink flipped mid-`npm run bundle`, mixed shim/package generations.

## Suggested approach (V1)
Acquire one `filelock` on `remotion/.astrid-registry.lock` at the top of `render()`'s remotion branch (before L1443), holding it through generation **and** the Remotion subprocess (L1493) — release in `finally`. Mirror `_lock_for` from asset_cache.
