## Unknowns
Whether external tools (remotion JS, reigh-app bridge) read sidecars outside this repo; failure-mode cleanup (mp4 exists, sidecar missing → never cleaned).

## Risks
Non-atomic write (:1232) and delete (:1149-1150); `timeline` matching uses resolved paths (v2 must keep `timeline` or provide projection); ffmpeg-path renders lack sidecars → invisible to cleanup; read-modify-write in audio-reactive (:1347) breaks if v2 serialization changes.

## Suggested approach
Add `schema_version` guard + compatibility projection layer mapping v1→v2 (keep `timeline`, `engine`, `resolved_effect_ids`, `registry_hash`); make writes atomic (tmp+rename) and delete sidecar+mp4 via single rename-to-trash; emit sidecars from `_render_ffmpeg_media`.
