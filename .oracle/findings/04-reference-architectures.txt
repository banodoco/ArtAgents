## Composite Reference Architectures — Verified Findings

**1. Remotion.** Track stacking is React DOM layering: visual tracks render in **reversed** array order (later = on top) — `astrid/packs/_core/skill/SKILL.md:596` (mirrored in `tests/fixtures/renderer_packs/hyperframes/render.py:272` and `remotion/src/ThreeTimelineComposition.tsx:33-39`). Alpha renders are supported via `--codec vp8/vp9`/prores-4444 + `--pixel-format=yuva420p|yuva444p10le` + `--image-format=png` ([remotion.dev/docs/transparent-videos](https://www.remotion.dev/docs/transparent-videos)); local config uses JPEG, no alpha (`remotion/remotion.config.ts:11`). `<ThreeCanvas>` is a DOM `<canvas>` (R3F wrapper, `frameloop='never'` during render) — it composites with sibling React elements via CSS stacking, and the scene adds `<color attach="background">` (`ThreeTimelineComposition.tsx:28-29`; [three-canvas docs](https://raw.githubusercontent.com/remotion-dev/remotion/main/packages/docs/docs/three-canvas.mdx)).

**2. FFmpeg.** Today Astrid uses **concat only** — trim/scale/pad/`format=yuv420p` then `concat` (`astrid/packs/rendering/backends/ffmpeg/command.py:272-283`); finalizer stream-copies (`finalizers/ffmpeg/run.py:2-6`). The layered alternative: `[0:v][1:v]overlay=...:format=auto[l1]`, chained `[l1][2:v]overlay...[l2]` in z-order; alpha via `format=yuva420p`; per-layer opacity via `format=rgba,colorchannelmixer=aa=<op>`; blend modes via `blend=all_mode=multiply` ([overlay](https://ffmpeg.org/ffmpeg-filters.html#overlay-1), [blend](https://ffmpeg.org/ffmpeg-filters.html#blend)).

**3. HTML/CSS.** Hyperframes stacks `.clip` with `z-index` per track (`render.py:273-276,333,376`), `data-track-index` as a timing lane, `data-layout-allow-overlap` on root (`:301`), plus an `inset:0` background div (`:310-312`). No `mix-blend-mode` and opacity≠1 is **rejected** (`:209`) — CSS would give both for free.

**4. After Effects.** "Layers at the bottom of the layer stacking order… are rendered first" ([composition-basics](https://helpx.adobe.com/after-effects/desktop/work-with-compositions/composition-settings/composition-basics.html)); blend modes "control how each layer blends with… layers beneath it" — Normal, Dissolve, Additive, Complex (Overlay/Soft Light…), Matte (Stencil/Silhouette Alpha/Luma), Utility ([blending-modes-layer-styles](https://helpx.adobe.com/after-effects/desktop/work-with-layers/work-with-layer-blending-modes/blending-modes-layer-styles.html)); plus track mattes (alpha/luma), opacity, precompose/nesting.

**5. NLEs.** Premiere: "clips on upper video tracks…" superimpose over lower ones; opacity/blend per clip ([Premiere Elements transparency](https://helpx.adobe.com/premiere-elements/desktop/applying-special-effects/superimposing-transparency.html)). Resolve: incoming clips go "to the topmost video track so they are above any previously existing" (DaVinci Resolve Reference Manual).

**6. WebGL.** three.js painter-sorts transparent objects back-to-front; `renderOrder` overrides it — local: "`mesh.renderOrder = trackIndex`… independent of three.js' internal transparent sort", z = −paintIndex (`ThreeTimelineComposition.tsx:33-39`); invoked as `THREE_COMPOSITION_ID` (`backends/threejs/run.py:77`). A transparent WebGL layer merges with other engines through RGBA alpha at the composite pass.

**7. Shared pattern:** bottom-to-top z-order, per-layer opacity + blend mode, alpha channel, background layer, one final composite pass.

**The shared layer vocabulary Astrid should adopt:** `layer { z_index, blend_mode, opacity, alpha }` · `compositor` = ordered pairwise pass: `dst ← blend(src over dst, blend_mode, opacity)` bottom→top · `background` (opaque default) · output pixel format with alpha (`yuva420p`/`rgba`) when any layer is transparent.
