## Findings (ranked)

**1. Planner canvas divergence (critical).** Hybrid planning reads only `timeline_data["theme_overrides"]["visual"]["canvas"]` with hardcoded 1920×1080@30 defaults (run.py:390–396 `_timeline_canvas`). Remotion resolves theme+overrides via `resolve_timeline_theme` (banodoco_composer.py:299–318, deep-merge at 267–296), passed as props (run.py:366–387, 1463–1472), and `getCanvas` falls back `visual?.canvas ?? props.theme?.visual?.canvas ?? DEFAULT_CANVAS` (Root.tsx:36–46). If canvas lives only in theme.json, planner plans 1920×1080@30 while Remotion renders the theme canvas — segments and concat are mis-scaled. Root.tsx default is 1920×1080@30 (Root.tsx:15–34).

**2. Complexity triggers** (`_complex_clip_windows`, run.py:692–763): effects, transition, non-base visual track ("overlay"), opacity≠1.0, audio fadeIn/fadeOut params (706–718); base track = max media coverage (696–702). Transitions expand window by `duration`/`durationFrames`/`8/fps` + 0.25s handle (724–743). Speed changes aren't a trigger — ffmpeg *rejects* speed≠1 (500–501) and overlapping audio (513–514), so only Remotion handles those.

**3. Boundaries** (`_hybrid_segments`, 766–784): duration ceil'd to frame grid (768); windows floor/ceil'd via `_round_frame_time` (430–438); 0.25s handle default; overlap-merged (756–762); cursor alternates ffmpeg/remotion.

**4. Speed/opacity in windows**: `_window_clip` remaps source `from/to` by `speed` and clips `hold` (447–466); windowed timeline keeps `theme_overrides` (469–488).

**5. `_concat_segments` (787–824)**: hardcoded `fps=30` + `yuv420p` (793) and 44.1kHz stereo (794); always re-encodes libx264 veryfast crf20 / AAC 192k (809–818); no probing — assumes every segment has v+a streams; **fps=30 forced even if canvas fps≠30**.

## Verified facts
- Hybrid = pure ffmpeg when no complex windows (770–771, 834–835).
- Remotion segment props use merged theme; planner doesn't.

## Unknowns
- Overlapping audio in an ffmpeg-planned window: validator raises (513–514); whether caught per-segment is untested here.
- Transition `duration` units (frames vs seconds) ambiguous in 728–731.

## Risks for porting
- Theme-file canvas ignored at plan time; fps mismatch vs concat's hardcoded 30.
- No stream probing in concat; audio-fade/overlay triggers depend on track-kind labels.

## Suggested approach
Add one merged-canvas resolver (`resolve_timeline_theme` + `_timeline_canvas`) shared by planner, Remotion props, and concat; pass fps into `_concat_segments`; probe segments before concat.
