**B2 — Generic TaskHandler adapter**
New `astrid/core/task_executor/generic_adapter.py`: one `CapabilityTaskHandler` implementing the `TaskHandler` protocol (service.py:113). **B3 — sdk.invoke admission: executors**

*Checkpoint:* process run of ≥3 executors via sdk.invoke → kernel events/receipts/terminal `succeeded`, zero run.json; executor test slice green after migration of assertions (E7 list).

**B4 — Orchestrators + children-as-kernel-tasks**

*Checkpoint:* process run of one orchestrator with N children → 1 run + N tasks, correct claimed/started/completed chains and dependent unblocks, zero run.json; video_editing test slice green.

**B5 — FS ledger retirement**

Fate per OQ2 (recommendation: delete, no projection).
*Checkpoint:* grep proves zero production run.json writers; full suite green; docs-alignment test updated.

**B6 — Docs v2 + final verification**

## 3. OPEN QUESTIONS

1. **Non-media output representation** — (a) nullable `task_outputs.media_id` [RECOMMEND: one ordered output ledger, matches ONE-store pillar]; (b) evidence_items only [splits primary-result semantics across tables]; (c) force everything through media [explicitly rejected by goal].
2. **run.json fate** — (a) retire outright [RECOMMEND: KISS; only ~3 internal readers to rewire]; (b) derived projection written at finalize [only if E6 surfaces external consumers]. If (b) ever ships, it must be written once from kernel state, never read back as authority.
3. **Orchestrator model** — one run + N child tasks [RECOMMEND: matches existing run→task hierarchy and dependency unblocking] vs N sibling runs [breaks progress derivation].
4. **Bespoke adapters** — delete after B2 parity passes [RECOMMEND] vs keep; keeping them violates "per-executor adapters where one generic path would do".
5. **`--out` (projectless) invocations** — kernel tasks require a project; (a) exempt and document honestly [RECOMMEND]; (b) synthesize a system project [new concept, scope creep].
6. **Evidence-primary role value** — reuse `role='result'` [RECOMMEND, zero extra DDL] vs new role vocabulary [needs CHECK change for nothing].

## 4. NORTH STAR CHECK

The plan advances the North Star directly: B1 makes the kernel accept every output class (minimal relaxation: one column); B2–B4 convert all invocation paths to kernel run+task via ONE generic adapter; B5 removes the second ledger rather than maintaining it; B6 forces docs to match shipped behavior. No serve/GPU supervision is built. Named anti-pattern risks: (i) OQ2(b) projection is one misstep from "second ledger by convention" — mitigated by defaulting to retirement and constraining any projection to write-once-from-kernel; (ii) retaining the two bespoke adapters past B2 parity would violate the one-generic-path invariant — plan deletes them pending evidence they add nothing; (iii) run directories persist as storage, which is not ledger authority — docs will say so explicitly.

Six batches, each ending in a green gate: kernel change (B1) is bounded; B2–B4 are mechanical once exploration lands; B5's risk is test-corpus breadth (~8 known files, E7 completes the census); B6 is mostly writing plus the empirical harness. Best estimate: **~4–6 focused agent-days** end-to-end including verification runs and review cycles.
