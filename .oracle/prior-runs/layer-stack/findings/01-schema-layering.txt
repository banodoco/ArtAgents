## Astrid Timeline LAYERING — Verified Findings

**1. TrackDefinition (banodoco_schema.py:172-183; enums 102-107).** `id`/`kind`(visual|audio)/`label` required; optional `scale`+`fit`(cover|contain|manual)=per-track viewport transform, `opacity`, `blendMode`(8 modes, 104-107), `volume`/`muted`=audio gain (ffmpeg/support.py:78-97: mute authoritative, track×clip gains multiply). `app` is an opaque string, allowlisted (363) but never consumed anywhere.

**2. Z-order = array order only.** No explicit zIndex. Reversed paint confirmed: ThreeTimelineComposition.tsx:33-39, 303-308, 360-364 (`paintIndex = visualTracks.length-1-trackIndex`, z=-paintIndex, renderOrder=trackIndex); hyperframes render.py:272-276, 321-333 (CSS z-index computed same way); SKILL.md:596 (`[...getVisualTracks(timeline)].reverse()`, "first visual track = top layer"); build_2rp_launch_timeline_v3.py:486.

**3. Clips.** `_CLIP_ALLOWED` (354-362): `opacity`, `entrance`, `exit`, `params`, `text` — **no clip-level blendMode**. ClipEntrance/Exit TypedDicts 185-195 (type/duration/intensity/params). Clip opacity≠1 is *rejected* by threejs (run.py:182-183) and hyperframes (render.py:209-210) — opaque layer semantics only at track level.

**4. Blend modes: schema-declared, never implemented.** Only consumer is ffmpeg/support.py:139-144, which *rejects* blendMode≠normal/opacity≠1/scale≠1 ("unsupported visual transform semantics"). No multiply/screen/overlay code anywhere; example only hype.timeline.full.json:53.

**5. Track flow.** RenderSegment = window+renderer+input_hashes only (contracts.py:1305-1357) — **segments don't know tracks**. Remotion declares `windows:False` (run.py:734-735), so service host-slices via `_window_timeline` (service.py:1096-1135), which **filters tracks to used ones** (1117-1122; same in legacy_hybrid/run.py:511-518) — track order/fields preserved, empty tracks dropped. Hybrid finalizer: "temporal concat only — there is no spatial compositing" (threejs-renderer.md:142-144).

**6. Audio.** First-class `kind:"audio"` (SKILL.md:646-650); visual backends reject audio tracks outright (threejs/run.py:154-163). Ownership contract rendered/passthrough/none (contracts.py:364-369); remotion always muxes RENDERED (run.py:816-824). Audio is a parallel axis, never spatially composited.

**7. Absent.** No zIndex/layer field (allowlists 350-363); no transparency flag beyond opacity; no background track — background is theme-level: `theme_overrides.visual.background`→`theme.visual.color.bg`→black (ThreeTimelineComposition.tsx:120-140; hyperframes render.py:305-312).

### Schema layering facts
- Paint order: reversed `tracks[]` array order; first visual track = top (SKILL.md:596)
- Stacking state: per-track `opacity`, `blendMode`; per-clip `opacity` only
- Blend modes exist only in schema/validation — every backend either ignores or rejects them
- Renderer contract collapses to time-slices: window+renderer, tracks filtered to used, no spatial compositing
- Background ≠ track; audio ≠ visual layer (ownership-declared, muxed separately)
