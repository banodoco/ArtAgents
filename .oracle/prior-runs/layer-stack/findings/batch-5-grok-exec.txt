### `legacy_hybrid/run.py` — architecture

Owns **window construction + renderer support selection only**. Never renders. `RenderService` re-resolves every pin.

Constants:

- `BACKEND_ID = "rendering.legacy_hybrid"`
- `FINALIZER_ID = "rendering.ffmpeg-finalizer"`
- Default simple renderers: `rendering.ffmpeg`, then `rendering.remotion`
- Default complex renderers: `rendering.remotion` only
- Handle: `Fraction(1, 4)` seconds

**Window algorithm** (`_complex_frame_windows` / `_segment_kinds`, 159–288):

1. Duration from `metadata.duration_seconds` / `expected_duration_seconds`, else max clip end.
2. “Base visual track” = visual track with the most media duration.
3. A clip is **complex** if it has effects, transition, is a non-base visual track, opacity ≠ 1, or audio fadeIn/fadeOut.
4. Transitions expand around the clip boundary by transition duration + 0.25s handle.
5. Merge overlapping complex windows; remaining spans are **simple**.
6. Simple → first supporting renderer in `simple_renderers`; complex → `complex_renderers`.

`support()` (437–480) only checks planner-level constraints (speed == 1, no overlapping audio, window FPS/bounds). It does **not** call renderer `support()`.

`plan()` (666–820):

1. `support()` first; fail closed.
2. `resolve_render_profile(...)`.
3. Load registries via `load_default_registries` unless injected.
4. Default `support_resolver = _CommandSupportResolver(...)`.
5. For each window, slice timeline with `_window_timeline`, call resolver, pin first supported renderer.
6. Emit `RenderPlan` with `requested_policy="hybrid"`, **no `layer` on segments**, finalizer `rendering.ffmpeg-finalizer`.

**`_component_timeline` (158–179)** — project the full timeline onto one occupancy component:

```158:179:astrid/packs/rendering/planners/threejs_hybrid/run.py
def _component_timeline(
    timeline: Mapping[str, Any],
    clips: Sequence[Mapping[str, Any]],
    indexes: Sequence[int],
) -> dict[str, Any]:
    """Project the timeline onto one component's participating clips.

    Only the tracks actually used by the component's clips are retained, so a
    timeline-level audio track that the component never touches does not
    poison an otherwise Three-eligible text component.
    """

    selected = [clips[index] for index in indexes]
    used_tracks = {clip.get("track") for clip in selected}
    component = dict(timeline)
    component["clips"] = selected
    component["tracks"] = [
        track
        for track in timeline.get("tracks", [])
        if isinstance(track, Mapping) and track.get("id") in used_tracks
    ]
    return component
```

Eligibility is **the exact Three.js text contract**, not a copy:

```182:196:astrid/packs/rendering/planners/threejs_hybrid/run.py
def _component_eligible(...) -> bool:

        _component_timeline(timeline, clips, indexes)
    )
```

**`_window_plan` (231–298)**:

1. Occupied clip frame ranges via `round(seconds * fps)`, min 1 frame.
2. Merge **strictly overlapping** `[start,end)` into connected components (touching ≠ overlap).
3. Component is Three iff **every** participant is text-eligible; otherwise whole component → Remotion (never split an overlap).

**How `support()` is called**

- `plan()` builds `segment_request` with a `FrameWindow` and a sliced `segment_timeline`.
- Resolver is called as `support_resolver(renderer_id, segment_request, segment_timeline)`.
- Because all three backends declare `supports_windows: false`, the resolver **materializes the sliced timeline to disk and clears `window`** before invoking backend `support()`. That is why Remotion/Three/FFmpeg never see a native window from the planner.

**How `support_decision` is built**

1. Backend (or static fallback) returns a `SupportReport`.
2. Planner checks `candidate_report.backend == registry.get(renderer_id).id` (alias-safe).
3. If `supported`, that report is passed into `_renderer_resolution(...)`.
4. `RendererResolution.support_decision = report` (required; must match renderer id).
5. Planner’s own `support()` report is stored on `PlannerResolution.support_decision`.

**Tiling rules in `RenderPlan.__post_init__` (1511–1547)** — this is the contract a layer-stack planner must satisfy:

- All segments have `layer` **or** all have `None`. Mixed is invalid.
- Per `layer.z` (or default `None`), segments must be contiguous half-open tiles, in order, no overlaps/gaps **between segments of that z**.
- Default layer (`None`) must cover the full target window (today’s exact concat).
- Explicit z layers may **end early** (overlay shorter than the timeline). Compositor background fill covers the rest.
- Distinct z values **may overlap in time**.
- FPS of every window must match the plan profile.
- `reasons` must have exactly one key per segment index.

Existing planners never set `layer`, so they are on the default-layer exact-tile path.

`FrameWindow`: `[start_frame, end_frame)`, `end > start`, `fps_rational` required.

## 9. `plan()` / `support()` protocol — **not stdin**

Wire contract (`docs/contracts/render-backend-v1.md:152–178`, `transport.py:166–182`):

```
<command...> plan    --request <abs.json> --result <abs.json>
<command...> support --request <abs.json> --result <abs.json>
```

- stdin is `subprocess.DEVNULL`.
- Request/result are files. Result file is the only protocol channel.
- Workspace = parent of `--request`.
- cwd = pack root. Do not write outputs there.
- Env gets `ASTRID_RENDER_BACKEND=<qualified id>`.
- Exit 0 even on structured failure; write `RendererError` JSON to `--result`.

Planner `main()` (legacy 853–887, threejs 654–687):

1. Parse verb + `--request` + `--result`.
2. `RenderRequest.from_dict(json).for_backend(BACKEND_ID)`.
3. `support(...)` or `plan(...)`.
4. `write_json_atomic(result_path, response.to_dict())`.
5. On exception, write `make_renderer_error(...).to_dict()`. Always return 0.

`plan()` **function** signature (in-process, used by tests):

```python
plan(request, *, workspace, support_resolver=None, registries=None) -> RenderPlan
```

Service path (`service.py:1312–1331`): `_select` calls planner `support`, then `_execute_planner` invokes command `plan` via transport. Service then **re-resolves every pinned renderer**, rechecks support, materializes windows.

**Pack-root launcher caveat** (`astrid/packs/rendering/run.py:96–117`): `[python3, run.py]` only routes planner traffic for `rendering.legacy_hybrid`. Threejs-hybrid uses a direct script path. If layer-stack uses `[python3, run.py]` you **must** add a launcher branch; otherwise follow threejs-hybrid:

```yaml
command: [python3, planners/layer_stack/run.py]
```

## 11. Backend `support()` — accept vs reject

All three backends: `supports_full_timeline: true`, `supports_windows: false`. They reject `request.window is not None`. Planners therefore must slice first.

### `rendering.threejs` — text / visual-only

`_support_reasons` (`backends/threejs/run.py:146–211`):

| Accept | Reject |
| --- | --- |
| `clipType == "text"` only | media, effects, any other clipType |
| visual tracks; empty/background OK | any `kind=="audio"` track present |
| exact `text` keys: content/fontSize/color/align/bold | unknown text fields |
| exact `params`: anchor/offsetX/offsetY/textShadow/maxWidth/weight | unknown params |
| opacity 1 or missing | opacity ≠ 1 |
| no effects/transition/animation | those present |
| clip/track gain == 0 | any audible gain |
| canvas w/h/fps positive ints | missing canvas |
| `audio=rendered` (always muxes AAC) | other ownership |
| full timeline | native window |

Features advertise `media_textures: false`, `effects: false`, `windows: false`, `alpha_output: true`.

### `rendering.remotion` — generalist

`support()` (`backends/remotion/run.py:766–893`):

| Accept | Reject |
| --- | --- |
| media + registered non-media clipTypes (text, effects, transitions via Remotion element registry) | unknown clipType |
| missing assets | listed as reasons |
| full timeline, effects, windows=false | native window |
| `audio=rendered` always | passthrough/none |
| profile must match mux profile (H.264/yuv420p/MP4, or ProRes/yuva444p12le/MOV if `astrid_layer.alpha`) | profile mismatches |
| node + npx present | missing binaries |

This is the fallback for anything Three/FFmpeg cannot do.

### `rendering.ffmpeg` — media-only, sequential

`structural_reasons` (`backends/ffmpeg/support.py:244–370`):

| Accept | Reject |
| --- | --- |
| **exactly one** visual track | 0 or >1 visual tracks |
| `clipType == "media"` (plus optional single `audio-reactive-colour` specialization) | `text`, other clipTypes |
| at least one visual media clip | empty visual |
| visual clips tile with no gap/overlap | gaps, overlaps |
| sequential audio, no overlap, audio ends within visual span | overlapping audio |
| opacity 1, no effects/transitions/transforms | effects, transition, fadeIn/fadeOut, non-default opacity/scale/fit/blend |
| assets registry required | missing registry |
| full timeline | native window |
| no backend_config | any ffmpeg config |

Plus probe checks: visual sources need video streams; audio sources need audio; visual clips requesting embedded audio that ffmpeg would drop are rejected.

## How the service already consumes layered plans

This is the rest of the layer-stack surface a new planner should target.

`RenderService._materialize_window` (`service.py:1086–1100`):

- slices by `segment.window`,
- if `segment.layer` is set, **keeps only `layer.tracks`** (even empty tracks stay),
- stamps:

```python
materialized["metadata"]["astrid_layer"] = {"z": segment.layer.z, "alpha": segment.layer.z > 0}
```

z>0 → Remotion/Three switch to ProRes 4444 alpha MOV.

Finalizer already exists: `rendering.ffmpeg-compositor` (`finalizers/compositor/`). Overlay bottom-to-top, short layers pad, output length = `plan.total_frames`. Existing planners still pin `rendering.ffmpeg-finalizer` (concat). A layer-stack planner should pin the compositor.

## Implementation recipe for `rendering.layer-stack`

Mirror `threejs_hybrid` (the newer, cleaner planner):

1. Add `astrid/packs/rendering/planners/layer_stack/{__init__.py,planner.yaml,run.py}`.
2. YAML: `id: rendering.layer-stack`, `command: [python3, planners/layer_stack/run.py]`, `operations: [support, plan]`, a new `policies` entry (e.g. `layer_stack`).
3. Register in `pack.yaml` planners list.
4. Update `test_freeze.py` planner id set (and any manifest path list).
5. Reuse `_CommandSupportResolver`, `_window_timeline`, `_load_inputs`, `_renderer_resolution` from legacy.
6. **Do set `layer=LayerRef(...)` on every segment.** All-or-none.
7. Per z: contiguous tiles; z layers may end early; different z may overlap.
8. Pin `rendering.ffmpeg-compositor`, not ffmpeg-finalizer.
9. Partition **tracks** into z-layers, then run temporal classification *inside* each layer (Three text vs Remotion/FFmpeg media). `_component_timeline` is the model for “don’t let unused audio tracks poison eligibility.”
