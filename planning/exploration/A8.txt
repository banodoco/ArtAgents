## Risks & conflicts

1. **Font non-determinism is the biggest risk.** The plan says "byte-identical PNG in a pinned runtime" but every existing Pillow user in Astrid depends on system fonts. System font rendering varies by OS, font version, and even fontconfig cache state. The storyboard's fallback to `load_default()` produces a tiny bitmap font that would violate the 24px minimum body-text rule.

2. **No SVG rasterization path exists.** The plan assumes SVG + PNG from one layout model, but offers no concrete SVG→PNG bridge. `cairosvg` depends on Cairo (system library), making it non-trivial across platforms. `resvg-py` is pure Rust with wheels — more deterministic but less common.

3. **Pillow is unpinned.** `pillow>=10.0` means CI could resolve 10.2, 10.4, or 11.0 on different days. PNG compression output is not guaranteed byte-identical across Pillow versions even with the same `compress_level`. The plan explicitly acknowledges this (plan:954-955: "compare decoded pixel buffers") but the storyboard test at line 316 asserts raw byte equality — an inconsistency to resolve.

4. **No macOS CI.** The plan mentions "supported platforms" plural, but only ubuntu-latest exists in CI. darwin arm64 (the development platform) has no automated verification.

5. **Fixture doesn't exist.** Density/pagination rules cannot be validated without the `desert-plant-growth` fixture. The 16-second claim in the plan may be stale — the plan also mentions an "expected" 98-second multi-track timeline for density testing.

## Elegant simplifications

1. **Bundle one font, skip the font-fallback ladder.** Ship a single open-source font file (e.g., `Inter-Regular.ttf` + `Inter-Bold.ttf`) inside `astrid/packs/rendering/executors/timeline_visualize/fonts/`. Use `ImageFont.truetype(str(bundled_path), size)` with no fallback. This makes font rendering deterministic across all platforms with zero environment dependencies.

2. **Skip SVG rasterization for M1 — render SVG+PNG independently from the layout model.** The layout model already knows every box position, label, and color. Pillow can draw the same geometry directly without needing to rasterize SVG. The SVG renderer writes `<rect>`, `<text>`, `<line>` primitives; the PNG renderer calls `draw.rectangle()`, `draw.text()`, `draw.line()`. Both consume the same `LayoutPage` objects. This eliminates the need for cairosvg/resvg entirely — at the cost of needing careful parity testing, but that's already required by the plan's exit gate (plan:854-856).

3. **Use the existing `compute_sha256` + `verify()` machinery unchanged.** The integrity module (`astrid/core/timeline/integrity.py`) already handles the exact ok/missing/mismatch states the evidence pack needs for source asset verification and snapshot hashing. No new hashing code required.

4. **Pagination rule of thumb (grounded in plan constants, not fixture):** At 1920×1080 with 80px min track height, 60px ruler, and 40px header/footer = ~960px usable for tracks = **12 tracks per vertical page**. At 100 px/s (comfortable density for 16s timeline), 1920px fits ~17s per page with gutters. At 20 px/s (minimum for 98s timeline), ~90s per page. So: **ceil(tracks/12) vertical pages × ceil(duration_s × px_per_s / 1800) horizontal pages**. The plan's 98-second multi-track case would paginate to roughly 2×2=4 pages time-scaled or 1 linear page. This should be configurable but the defaults are sound.
