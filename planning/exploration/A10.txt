### 2. `timeline_storyboard`: remote fallback, timestamps, and positional-ID policies

**Remote fallback** (`run.py:145-146`, `:171-176`, `:357-359`, `:452`):
- `_is_remote_source()` treats `http`, `https`, `data`, and `file` URIs as remote (`run.py:146`).
- Asset resolution falls back URL → thumbnail URL if local file is missing (`run.py:171-176`). This means the storyboard **will render remote images in HTML** (`_html_source` passes them through as `src` attributes, `run.py:357-359`).
- The contact sheet (PNG) **refuses** remote sources — `_paste_contact_sheet_image` skips missing and remote (`run.py:452`).
- **Why visualization must not inherit this**: The visualization epic requires "verified original media" with "no remote fetch" (North Star invariants). Remote URL fallback would silently accept unverified sources. The storyboard's leniency is appropriate for an editing preview but violates the visualization's evidence contract.

**Timestamps** (`run.py:16`, `:735`):
- `datetime.now(timezone.utc).isoformat()` used for manifest `created` field only (`run.py:735`). This is a manifest metadata field, not a content timestamp.
- **Why visualization must not inherit**: The visualization epic requires "snapshot-safe" determinism. The manifest timestamp is metadata, not content, but any `datetime.now()` in the rendering path creates non-deterministic outputs. The storyboard already has this correctly scoped (manifest only), but visualization's evidence pack must be fully reproducible from frozen inputs.

**Positional-ID policies**: 
- The storyboard **inherits** shot IDs from `pinnedShotGroups[].shotId` and falls back to `shot-{index+1}` (`run.py:295`). Shot ordering is determined by `pinnedShotGroups` array index (`run.py:292`).
- Asset IDs are read from the registry (`run.py:68-74`), normalized by stripping `asset:` prefix.
- **Why visualization must not inherit**: The visualization plan mandates **deterministic stable display IDs** (`TL01`, `CL01`, etc.) derived from canonical object identity and ordering, not from array-position fallback. The storyboard's `shot-{index+1}` positional fallback is fragile — reordering `pinnedShotGroups` changes IDs, breaking the stable-ID invariant.
