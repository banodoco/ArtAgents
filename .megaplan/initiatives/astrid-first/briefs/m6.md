# m6 — Serve, backup, doctor and teardown (sprint-plan Sprint 6)

Normative references: `docs/unified-data-model-plan-v10-20260813.md` (§2 layering, §3 Phase 2, §4.3, §5.3 items 9/10/11), `docs/astrid-first-sprint-plan-20260813.md` (Sprint 6), `docs/astrid-first-sprint-plan-review-20260813.md` (fixes 4/6/7). Plugin/generalization feedback source: `docs/openrouter-chat-20260814-plugin-data.md`.

## Outcome

The product is complete as a runnable local system: **`serve`** (lazily initializes the app DB + data dirs, registers the three in-tree packs, starts the repository bridge, opens the chosen editor path — no account/cloud/provider required), **`backup`/`restore`** (SQLite online backup + managed-media directory copy, staged restore with validation, idempotency-key/replay/envelope conformance per review fix 6), **`doctor`** (SQLite quick check + FK validation + core/installed-pack schema versions + media/data paths; read-only — never a repair framework), and **teardown** of old authorities. File/JSONL/FSA/Supabase semantic writers and old CLI families/verb families are deleted; exactly eight top-level families now complete and gated (`projects`, `timelines`, `media`, `tasks`, `runs`, `serve`, `doctor`, `backup`); no migration-era terminology or continuity machinery remains.

## Scope

IN:
- `serve`: startup sequence, DB/data-dir init, bridge start, editor open (version-matched bundle or chosen current path), readiness; failures are visible and typed, no silent fallback.
- `backup create`/`restore`: writer-lock pause, online backup, media-dir copy, exclude caches/staging/logs/packs/secrets; restore stages, validates (quick/FK + media verification on open), swaps after validation; idempotency/replay/envelope tests (review fix 6).
- `doctor`: quick_check, FK violations, schema-version compatibility, data/media path checks; stable `--json`; deliberate corruption → stable fail-closed codes.
- Teardown: remove old file authorities (project/timeline/run JSONL, sidecars, threads/session/lease files), old CLI families, FSA and Supabase paths. Extend import/schema lint to forbid removed-authority imports, kernel-to-pack FKs/imports, and pack-owned/direct writers; help shows exactly eight families; secret-sink + allowlisted-child-environment tests run in the gate (review fix 6).

OUT: dogfood (m7), packaged-artifact GA proof (m8).

## Locked decisions

- v10 §4.3 backup/doctor scope (no manifest machinery, no repair framework); exactly eight CLI families; decision-artifact platform matrix is the tested surface.
- Backup/restore idempotency resolution recorded (m4 decision or v10 amendment note — must exist before this milestone ships).
- Secrets never enter backups; external-local media excluded with surfaced risk + `media relocate` offered.

## Open questions

- Backup destination format/layout (directory structure, naming) — propose + freeze here.
- Whether `timelines copy` CLI verb lands here (bridge route already planned in m4).

## Constraints

- GA items 9/10/11 (v10 §5.3): backup/restore restores a usable project; clean install without account/cloud/provider secret; removed authorities absent from the release artifact/help; import lint green.
- Doctor stays read-only; no generic repair language; crash/contention suites still green. Backup/doctor operate over the single SQLite file and managed-media root irrespective of the installed in-tree packs.

## Done Criteria

Sprint-6 gate: `serve` boots a clean project end to end and registers exactly the declared in-tree packs; backup→destroy→restore reopens with matching hashes/events/heads and pack migration state; doctor is clean on fresh/restored projects and gives stable codes on corruption; exactly eight families appear in executable help with the declared kernel/pack ownership and nested mounts; static/schema lint finds no Supabase/FSA/JSONL semantic writer, kernel-to-pack FK/import, or pack-owned/direct writer in product paths; secret-sink tests are green.

## Touchpoints

- reigh-timeline-main: editor path opened by serve; provider tests still green.

## Anti-scope

No dogfood/hardening (m7); no packaged-artifact proof (m8); no legacy import; no remote execution; no experiments/publish/accounts; no schema changes; no new families beyond eight; no editor feature work.
