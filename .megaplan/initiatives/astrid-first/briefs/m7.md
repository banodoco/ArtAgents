# m7 — Dogfood and hardening (sprint-plan Sprint 7)

Normative references: `docs/unified-data-model-plan-v10-20260813.md` (§5.3), `docs/astrid-first-sprint-plan-20260813.md` (Sprint 7), `docs/astrid-first-sprint-plan-review-20260813.md` (fix 7 — S7 proves items 1–10 plus provisional item 11; plugin factoring adds item 12).

## Outcome

The system is exercised like a real product and attacked where it can fail: representative fresh-project journeys (editor project → timeline save → media import → generation/render → references/shots → backup/restore) run end to end; failure modes are injected (crash at every transaction boundary, kill during backup/restore, corrupted media, missing media, stale saves, two-tab contention, schema-version mismatch); GA items 1–10 pass on an unpackaged release candidate, item 11 has **provisional** source/build proof, and item 12 retains its m3 source/test proof pending the final installed-artifact rerun in m8; performance budgets on the representative fixture are measured; documentation is verified from clean-machine examples.

## Scope

IN:
- Dogfood journeys (scripted, reproducible): the five-domain + serve/backup/doctor flows from a fresh checkout; editor save/409/draft-recovery/asset-Range through the real bridge.
- Hardening: crash-injection matrix (statement boundaries, backup, restore, migration), media mutation/missing detection UX, contention (two tabs + executor + CLI), corruption → doctor codes, orphan staging GC, migration-version mismatch refusal.
- Performance: representative fixture measurements (bootstrap, gallery, timeline load, save, change feed, media verify) vs the v10 §6 budgets; report cold vs warm.
- Documentation: clean-machine examples verified; failure UX documented (unavailable/migrating/schema-incompatible states).
- GA items 1–10 + provisional item 11 evidence pack; retain the m3 item 12 factoring evidence for the m8 artifact rerun.

OUT: final packaged-artifact proof (m8).

## Locked decisions

- v10 §5.3 acceptance items 1–12 are the target; this milestone proves 1–10, carries provisional 11, and retains m3's source/test proof for 12 (review fix 7 plus the plugin factoring addition).
- Doctor is read-only diagnostics; hardening finds defects, fixes go through repositories with tests.

## Open questions

- Which representative fixtures count as "representative" (size/shape) — freeze from the m6 performance baseline; note any budget that forces a plan change.
- Any GA item that fails → record, fix via repository/test change, re-run; escalate to the chain only if the failure is architectural.

## Constraints

- No new features; no schema changes; no scope growth; fixes must not weaken v10 invariants; buffer may close gates, never add deferred scope.

## Done Criteria

All twelve GA items evidenced at the appropriate stage (1–10 fully, 11 provisionally, 12 from m3 source/test proof pending m8 artifact rerun); crash/contention/corruption matrix green with stable codes; performance report meets or explains every budget; clean-machine docs verified; defect count + fixes recorded.

## Touchpoints

- Astrid repo: test harnesses (`tests/`), CLI/SDK, `doctor`, backup/restore; reigh editor provider tests.
- Docs: v10 §5.3, sprint-plan §3 Sprint 7, review fix 7.

## Anti-scope

No packaged-install proof (m8); no new features; no legacy; no remote; no editor changes; no schema changes; no deferred subsystems.
