# m4 — Bridge, SDK and CLI domains (sprint-plan Sprint 4–5: bridge + five domain families)

Normative references: `docs/unified-data-model-plan-v10-20260813.md` (§2 layering, §4 CLI/SDK/bridge, §5.3 items 6/10), `docs/astrid-first-sprint-plan-20260813.md` (Sprints 4–5), `docs/astrid-first-sprint-plan-review-20260813.md` (fixes 4/6). Plugin/generalization feedback source: `docs/openrouter-chat-20260814-plugin-data.md`.

## Outcome

The product surface for the editor and the five domain CLI families: the **bridge is completed over the frozen wire contract** — timeline list/load/save with CAS, asset GET/HEAD with Range/ETag, project routes, typed errors — with all editor data flowing through registered repositories (current `AstridBridgeDataProvider` tests + bridge contract tests green in CI); the **SDK** (Python) exposes typed project/timeline/media/task/run services with stable envelopes, idempotency keys and typed errors; the **five domain CLI families complete**: kernel `projects`, `media`, `tasks`, and `runs`, plus `timelines` contributed by the timeline pack. Shots mount below `timelines`; references mount below `media`. These are manifest-declared in-tree mounts, not dynamic plugin loading or extra top-level families. Decision artifact's platform matrix owner delivers the frozen OS/browser/package targets.

## Scope

IN:
- Bridge: full route surface for editor needs (timeline GET/list/save, assets with Range/ETag, project basics), repository-backed, no fallbacks; error envelope to wire shapes (409/422/404); editor provider + bridge contract tests in CI.
- SDK: typed services for the five domains (+ reference/shot services), stable JSON/error envelope, idempotency keys on mutations, receipts returned; SDK is the thin client the CLI wraps (no second implementation).
- CLI: kernel-owned `projects`, `media`, `tasks`, and `runs`; timeline-pack-owned `timelines`; shots-pack `timelines shots ...` and references-pack `media references ...` nested mounts, all with typed output/errors/help. `media import|verify|relocate|relate` acceptance includes event/head/receipt/replay/mismatch/statement-boundary coverage (review fix 5); `tasks` cancel/retry; `runs` group progress.
- Bridge/CLI/service composition consumes each in-tree pack's registered repository and declared mounts through the shared kernel services; no handler loads a pack dynamically, opens SQL, or becomes a writer.
- Operational idempotency decision: record (or amend v10 §4.1) how mutating commands carry idempotency keys; backup/doctor idempotency resolves here for m6 (review fix 6).

OUT: `serve`/`doctor`/`backup` (m6), packaging (m6), teardown (m6), editor feature work (never).

## Locked decisions

- v10 §4 CLI/SDK contract; bridge wire contract frozen (m1); exactly eight top-level families total — five land here, three in m6 (review fix 4).
- SDK is the single client implementation; CLI is a thin wrapper.
- The eight-family rule is ownership-aware: the kernel owns seven eventual families (`projects`, `media`, `tasks`, `runs`, `serve`, `doctor`, `backup`), the timeline pack contributes the eighth (`timelines`), and shots/references remain nested pack mounts.
- Secrets: provider invocation resolves explicit option → process env → OS keychain; env files never override process env; secrets never enter events/receipts/task specs/logs/backups (v10 §4.3).

## Open questions

- No browser work beyond the editor's existing provider tests.
